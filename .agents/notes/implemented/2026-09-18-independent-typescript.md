# Agent Note: 独立 TypeScript 工程与固定语境卡片

Status: implemented

## 为什么

学习卡片应围绕触发它的词和原文展开，卡片内继续换词会改变讨论对象。准备开源需要独立的运行身份、安装配置和可复现工程，不应依赖早期原型的目录与浏览器缓存。

## 决策

统一卡片打开后固定选词、来源与自动请求的释义；只有想法可编辑。保留收藏、保存和复制讨论上下文。

采用 TypeScript/pnpm workspace、Vitest/V8、tsc、esbuild、Lefthook。分离扩展、CLI、本机桥接和 SQLite 核心。设置使用独立 namespace，供应商适配器独立实现。安装器要求明确 ID 和目录，Node 入口打包后不引用开发 checkout。SQLite schema v1 与数据目录保持兼容。

安装目录使用 Context 自己的名称。迁移时先保留配置、卸载旧扩展、从独立目录加载，再按新 ID 注册本机桥接；SQLite 沿用原资料库。README 补充独立目录布局和变更 ID 的重装步骤。

用户进一步确认产品与运营工作区不承担开发职责。开发仓库整体迁出产品工作区，保留 Git、源码和工程配置；原始产品需求、Agent 原生探索及历史视觉研究归产品工作区。工程接收需求摘要与验收条件，不依赖私人产品文档路径完成构建。

## 放弃了什么

不复制参考工程的企业容器、DSH profile 或私有服务；不保留原型旧缓存/设置页面。没有为了独立品牌删除法定第三方许可。没有自动发布到公开远程。

## 怎么验证

Vitest 42 项测试通过，另有 1 项 skill 测试通过，覆盖固定选词、笔记写入、上下文复制、跨资源授权、SQLite事务、任务缓存、CLI和桥接协议。核心四项覆盖率100%；发布烟测解压实际 ZIP、安装并移除安装介质后验证 CLI 数据持久化。类型检查与文档/打包门禁全部通过。macOS Chrome 已确认扩展版本 0.2.0，资料库经新版桥接正常显示原有 4 个资源；未写入测试学习记录。Linux/Windows 安装尚未在真实平台验证。

macOS 完成旧扩展卸载与独立目录重装实测：Chrome 显示新安装来源及新 ID，两项服务密钥恢复，资料库读取 4 个资源，CLI 统计与迁移前一致。旧目录移到废纸篓，临时迁移页面和密钥文件已清理，未纳入发布包。

开发仓库迁出产品工作区后，在新位置完整运行 CI 通过，包括发布包独立安装验证。已检查工程 hooks 和命令入口中的旧路径，Chrome 安装与稳定 runtime 无需随源码迁移。
