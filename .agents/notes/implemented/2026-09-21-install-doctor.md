# Agent Note: 外部 Node 与只读安装诊断

Status: implemented

## 为什么
用户选择暂不交付自带 Node，由本机 Agent 准备运行环境；需要可执行的诊断入口，避免把普通 status 当安装完成证明。

## 决策
Skill 先指导 Node/路径检查，CLI 可启动后运行 doctor。doctor 默认 JSON，只读打开已有 SQLite，报告相关表读取与历史心跳，不初始化、修复或调用服务。历史心跳 JSON 损坏单独报告，不误判数据库不可读；注册、实时握手和配置未知时明确 unknown。完整安装控制面仍是未来设计。

## 放弃了什么
暂不打包 Node、不实现自动 repair、不将心跳新鲜度作为实时连接依据；诊断不输出数据库内容或密钥。

## 怎么验证
真实 CLI 子进程覆盖不存在、损坏、相关表可读与历史心跳异常；检查诊断前后文件相同、缺失目录不创建。增加活跃 WAL 连接及真实发布包 doctor 验证；不承诺 SQLite sidecar 完全不变或锁争用已覆盖。沿用全量 CI 与逐文件覆盖率门禁。不新增首次安装实机验收。
