# Agent Note: 资料编辑与统一导航

Status: implemented

## 为什么

资料库编辑入口不完整，资源详情把返回导航与来源操作挤在一起，用户无法稳定定位当前层级。

## 决策

面包屑采用「资料库 / 当前分类 / 资源记录」，首项进入学习统计，详情沿实际入口返回（包括保留搜索词）。来源与编辑操作独立排列，不承担层级导航。侧栏切分类清空搜索过滤。

资源可编辑标题和分类；笔记编辑正文；词条修正同步关联出现记录的词面，语境释义单独编辑。稳定 ID、原文锚点、复习关系、创建身份与创建时间不变；同语言重名拒绝隐式合并。收藏按当前词面匹配，历史哈希占用时分配新 ID。所有写入使用修订号冲突检测和历史记录，CLI capabilities 暴露相同能力。失败保留输入，冲突要求重新读取，不自动覆盖。

删除统一为可恢复的回收站操作。仅在目标记录写 deleted 标志，默认列表/搜索/统计/讨论上下文根据资源或词条祖先状态隐藏关联记录；词条全局保留，删除单处语境不删除词条。恢复父项不会覆盖子项自己的删除标志。资源删除取消排队/执行任务，拒绝迟到结果，重新采集不能自动复活。Agent 与 UI 使用相同修订号、幂等和身份审计能力。回收站不提供永久擦除；备份可保留删除状态导入。

## 放弃了什么

不允许修改资源网址或原文锚点，避免破坏回溯；不把不同语境释义合并成全局释义；不在这个改动内实现词条合并。保留简单页面状态，未引入路由框架或浏览器历史管理。

## 怎么验证

公共 store 入口覆盖词条修正、重名/版本冲突、身份历史与重新收藏；JSDOM 使用真实临时 SQLite 验证各编辑入口、取消、冲突保留草稿和搜索面包屑返回。完整 CI 保持核心逐文件四项覆盖率 100%；交付时检查 Chrome 的实际布局，临时测试数据不写入个人资料库。删除回归覆盖共享词条、父子独立恢复、后台任务、备份、冲突/重复请求及 UI 确认取消。
