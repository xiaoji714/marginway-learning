# Agent Note: 产品 README 与演示资产

Status: implemented

## 为什么

主 README 原先更像工程说明，新用户难以快速理解语境与 Agent 延续讨论的价值，也没有可核实的产品画面。

## 决策

维持中文主 README，以产品演示和学习闭环为主体，工程内容只保留链接。安装步骤归 installation.md，测试与截图复现归 engineering.md，未来方案单独标记未实现。保留原品牌表达，准确说明私有仓库阶段、MIT 授权与外部服务边界。

新增只读本机演示入口，复用当前 common/library 构建产物，以临时 SQLite 与合成文本替换 Chrome/供应商边界。截取实际 DOM，不把演示包装页或静态释义当线上服务能力。

## 放弃了什么

不提交私人截图，不使用图像生成冒充已实现界面；不添加没有产品需求的双语 README；不增加尚不存在的商店或 Runtime 下载入口。

参考 Logseq 的价值优先、Karakeep 的定义后紧接实际截图与快速文档入口、Browser Use 的场景 Demo 与 Agent 文档分层；只借信息层次，不复制视觉与措辞。

## 演示规范收敛

README 以产品场景与演示图为主体；安装、CLI 协议、数据流和工程细节只链接各自文档。图片统一 960 显示宽度；视口高度按内容确定：卡片 1120×740、资料库 1120×840，避免固定比例导致过多留白。用户明确提供用于运行介绍的视频截图单独标注真实来源，不冒充合成资料，也不作为测试 fixture。具体制作规则归工程文档，不在 README 重复维护。

整体推广使用独立静态 HTML/CSS，简短标题与说明配未重绘的原截图。CSS 使用 mw-showcase 命名空间，便于未来前端复用；不引入新框架、JavaScript 或构建依赖。README 使用页面截图，源图及第三方归属保留。此前 AI 图仅为排版探索，避免小字重绘影响真实性。

## 怎么验证

在浏览器打开演示卡片和资料库，检查对应内容与截图；核心产品测试仍负责真实保存/恢复等行为。完整 CI 校验 TypeScript、既有回归、打包和文档预算；演示资产不含密钥或私人笔记；真实视频图为用户指定使用的资产。研究项的完成仅指方案，不代表未来安装器已发布。
