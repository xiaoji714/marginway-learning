# Agent Note: Hosted CI、版本体系与领域拆分

Status: implemented

## 为什么

首次远端 CI 在干净安装时被 pnpm 依赖脚本策略阻断。版本号分散硬编码，核心领域集中在单文件；来源拒绝测试可能因缺少配置提前退出。

## 决策

明确允许 esbuild/lefthook 构建，采用 GitHub-hosted 三平台矩阵。根版本统一校验和升版，包名由版本生成，构建 metadata 可追溯；手动工作流仅创建 Release 草稿。核心按资源、笔记、词汇复习、讨论、任务、备份拆分，事务/幂等仍统一由命令入口维护，SQLite schema 不变。来源拒绝测试使用有效安装 ID 和错误来源，并验证未创建数据库；补设置页失败路径、版本漂移与重装保留数据测试。

## 放弃了什么

不拆微服务，不改变 CLI/Native Messaging 协议、数据库目录或真实用户数据。不把核心100%覆盖率当作全应用100%；不自动发布正式版本。Windows 隔离安装烟测不注册真实 Chrome host。

## 怎么验证

完整 CI 检查类型、核心逐文件四项100%覆盖率、应用协议/UI测试、版本一致性与发布包独立安装。重构沿用既有业务契约测试验证行为；新增反例验证错误路径不会部分写入。远端结果以对应 PR 的三平台检查为准。

本地48项测试通过；GitHub-hosted Linux/macOS/Windows 首轮完整门禁全部通过。发布烟测另验证拒绝无关目录时不写 runtime，重装保留数据，并将所需工程/发布说明随包分发。仍未运行真实 Chrome 的跨平台自动化 E2E，也未触发 Release 草稿工作流。
