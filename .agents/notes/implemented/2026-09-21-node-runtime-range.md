# Agent Note: 区分 Node 运行兼容与开发基线

Status: implemented

## 为什么
精确锁定开发版本被安装指南误用为用户前提，导致 Agent 为已有兼容环境重复安装 Node。

## 决策
.node-version 保留可复现基线；根 engines 跟随当前开发依赖的兼容范围。发布包不带开发依赖，运行最低22.13.0并需通过 SQLite 能力检查；Skill 优先复用兼容环境。CI用同一构建包在22.13.0/24.0.0/26.0.0验收安装与CLI持久数据，由 pr-gate 聚合阻断失败。

## 放弃了什么
不把开发依赖降级来迁就旧 Node，不承诺仅凭版本号所有未来版本都可运行，不安装额外全局运行环境；用于验证的下载只留在忽略目录。

## 怎么验证
官方 Node 发行包按 SHA-256 校验，隔离安装/重装/资料读写和 doctor 烟测；POSIX 通过生成的 learning 启动器运行并核对绑定 Node，移除安装介质后再读数据；Windows 保留直接 JS 烟测、不宣称 cmd 入口已验证。全量 CI 与最终独立评审。兼容测试只替换被测子进程，测试驱动仍使用固定开发版本。不新增首次真实 Chrome 安装验收。
