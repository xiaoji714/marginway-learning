# Agent Note: 运行入口测试证据

Status: implemented

## 为什么
核心 100% 未包含浏览器动态脚本与 Node 子进程，已有用例无法说明应用运行代码覆盖范围。视觉与 Skill 文档断言也不能替代用户任务验证。

## 决策
保留核心 V8 门禁；运行应用在 TypeScript 转译前插桩并收集各隔离上下文及子进程计数，严格命令逐文件检查四项 100%。诊断报告与验收命令明确区分。浏览器端到端使用隔离 Chrome/Native/SQLite，在流程节点检查视觉；预置合成翻译、禁止收费请求、默认暂停。Skill 区分确定性 CLI 契约与真实模型任务记录。新增失败场景暴露字幕错误提示被轮询覆盖的问题，按位置保存错误直至切换资源；去掉已无调用入口的部分翻译旧函数。

## 放弃了什么
不把扩展源码简单加入 V8 include 后将零覆盖当作测试缺失；不通过降低核心阈值或忽略异常分支获得绿灯。不提交个人学习库或截图，也不把合成 YouTube 页面冒充真实站点验收。

## 怎么验证
运行原有完整 CI、应用报告和严格覆盖命令、GitHub Chrome 流程。严格命令低于 100% 时必须失败；浏览器基线经人工审图后才提交。覆盖缺口与尚未完成的浏览器/模型验收留在 Issue，不宣称闭环完成。
